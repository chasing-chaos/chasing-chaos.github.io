Interview Question Retro - When Neither System Is Trusted

Recently, I interviewed with a large data company. They asked an interesting question: “How would you run a dual-system migration when neither system can be treated as the truth?”

After the interview, I revisited the question. Here’s my thought:

1. We can separate different kinds of reference
- Production (customer-facing output / reporting): use the old system. New system does shadow run only.
- Truth: judge based on the original data source as opposed either system
- Baseline: diff uses the old system as the reference point

2. Say if two systems' results don’t match, we can first exclude false diff cases, e.g.,
- Design difference: maybe the new system is designed to calculate differently
- Timing difference: cut-off times, sync delays. We can recheck after one cycle & see if it’s a real problem

3. Reconcile the real diffs using sample & totals
- Full volume stays at aggregate reconciliation only to save cost
- We can use stratified sampling for details with human adjudication. The adjudicated golden samples get reused.

4. In the case when both systems make the same mistake, their outputs agree, and diff sees nothing, we can
- Reconcile totals back to the source using lineage
- Run a fixed golden sample through both systems on a schedule

5. We can cut over when unexplained diffs fall below field-level threshold. After cut-over, we can keep the old system read-only for at least a full close cycle with a rollback plan
